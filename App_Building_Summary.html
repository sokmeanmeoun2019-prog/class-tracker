The Journey: Building the Class Tracker App

A step-by-step master guide recounting the entire workflow, from the first prompt to the final public launch.

1 Providing the Initial Prompt

The journey began with a clear, detailed prompt describing the vision: A Teacher/Class Management Web App to replace manual spreadsheets. The prompt outlined the exact requirements, including pages for the Dashboard, Class Roster, Record Participation, Score List, and PTC (Parent-Teacher Conference) reports.

By providing such a structured prompt, the AI was able to immediately understand the scope and suggest a modern tech stack: React, TypeScript, Tailwind CSS, and Vite.

2 Local Setup & Environment Challenges

The next step was generating the project files on the local computer to test the app locally before launching it to the world.

The Struggle: "Access is Denied" Terminal Errors

We hit our first major roadblock immediately. The local Windows environment aggressively blocked the AI from running terminal commands (like npm run dev or npm run build) with an "Access is denied" error. We could write the code files, but we couldn't run or compile the app locally to see what it looked like.

The Solution: Coding "Blind"

Instead of giving up, we adapted. We established a unique workflow where the AI wrote and updated the code purely based on logical reasoning (coding "blind"), trusting that the React/TypeScript structure was correct, and skipping local preview testing entirely.

3 Launching Publicly to GitHub

Because we couldn't run the app locally, we moved straight to cloud hosting. The first step of deployment was pushing the code to GitHub.

We created a new public GitHub repository. Following a manual workflow, the src folder, package.json, and other configuration files generated by the AI were manually uploaded directly into the GitHub web interface. This established our "source of truth."

4 Deploying to Vercel.com

With the code sitting safely in GitHub, we logged into Vercel.com and connected the GitHub repository. Vercel is designed to automatically detect React/Vite projects, build them, and assign a live, public .vercel.app URL.

The Struggle: Vercel's Strict TypeScript Build Errors

This is where the hardest battles were fought. Vercel runs a very strict check (tsc && vite build) before allowing a site to go live. Because we couldn't run these checks locally, our Vercel builds failed repeatedly. We faced errors regarding:

  • Missing type definitions or interfaces.
  • Variables that could potentially be "undefined."
  • External libraries (like jspdf) crashing the build.
The Solution: Screenshot Debugging

The workflow became a tight feedback loop: Vercel would fail -> A screenshot of the Vercel error log was provided to the AI -> The AI fixed the exact line of code -> The updated src folder was re-uploaded to GitHub -> Vercel automatically rebuilt it. Eventually, we achieved the satisfying "Green Checkmark" of a successful deployment!

5 Expanding Features (Semester Exam & PTC)

Once the app was live, we began adding complex features directly into the live build loop. We built the highly customized Semester Exam section, complete with inline editing and a bilingual footer.

The Struggle: Data Contamination & Import Headaches

When typing a student's ID or Khmer name in the Semester Exam, it accidentally overwrote their global student profile. Furthermore, typing hundreds of exam scores manually was tedious.

The Solution: Isolated Records & Bulk Upload

We separated the exam data from the main roster, ensuring exam-specific data stayed in its own database lane. Then, we added a powerful Bulk Import Excel button that parsed `.xlsx` files and automatically matched rows to student names, instantly filling out the entire exam sheet in one second.

6 The Layout & Printing Battles

An app used by a teacher must be printable and usable on a phone, which introduced UI challenges.

The Struggle 1: The Trapped Print Scrollbar

When trying to print the Score List or Semester Exam as a PDF, the browser would print a tiny box with a scrollbar inside the paper, cutting off 80% of the students and the footer.

The Solution 1: CSS Print Media Queries

We meticulously applied print:overflow-visible and print:h-auto to the main layout wrappers. This stripped away the web-based scrollbars during printing, allowing the browser to naturally break the tables across multiple pages.

The Struggle 2: The Squished Mobile View

When accessing the live Vercel link on a smartphone, the permanent desktop sidebar took up 70% of the tiny screen, squeezing the main app into an unusable sliver. The huge header stats ("Total Students", "Today's Points") also stacked vertically, pushing the actual student list completely off the screen.

The Solution 2: Mobile-First Responsive Design

We implemented a completely dynamic layout. On mobile phones, the sidebar automatically hides itself behind a sleek "Hamburger Menu" toggle. We also compacted the stats into a single horizontal row (grid-cols-3) and shrank the date/class selectors, maximizing screen real estate so the participation tracker could be swiped smoothly with a thumb.

Final Result

Against all odds—and without a working local terminal—we successfully designed, debugged, and launched a massive, feature-rich React web application to the public internet using a purely cloud-based CI/CD deployment cycle.
